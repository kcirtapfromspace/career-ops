## Block F — Interview Plan

Netflix interviews assess both technical depth and culture alignment ("Freedom & Responsibility"). The loop typically includes: recruiter screen → hiring manager conversation → live technical screen → final loop (4-6 interviews: coding, system design, behavioral, team fit, culture).

### STAR+R Stories for Netflix

#### 1. [Distributed Systems] Data Movement at Scale — CDC Lakehouse
**S:** Needed to demonstrate end-to-end CDC architecture for real-time and batch data movement.
**T:** Build a working pipeline from PostgreSQL through Kafka to analytical layer.
**A:** Implemented Debezium CDC → Kafka → Spark → dbt/DuckDB → Evidence.dev. Added Great Expectations data quality gates. Orchestrated with Argo on Kubernetes.
**R:** Working open-source demo proving the exact pattern Netflix Data Movement Platform uses. Showed integration challenges (schema registry, exactly-once semantics) that only surface in end-to-end builds.
**Reflection:** End-to-end ownership reveals integration risks that component-level thinking misses. This is the mindset Netflix expects at L5.
**Best for:** System design interviews, "walk me through a technical project," data movement platform fit.

#### 2. [Developer Experience] Self-Service Pipeline Platform — Argo Workflows at Workiva
**S:** Workiva's data team needed a scalable pipeline platform. Existing deployment took days and required manual intervention.
**T:** Build enterprise self-service data pipeline platform on Kubernetes.
**A:** Designed CloudFormation infra (Aurora PostgreSQL multi-AZ, S3/KMS, Okta SSO). Implemented Helm charts for multi-cluster deployment. Created standardized workflow templates. Built Prometheus + New Relic observability.
**R:** Pipeline deployment from days to hours. 200+ analysts gained self-service access. Multi-cluster K8s orchestration in production.
**Reflection:** Developer experience is the multiplier — the best platform is worthless if engineers can't use it. This is the DDX team's entire mission.
**Best for:** DDX sub-team interviews, "how do you improve developer productivity," platform engineering depth.

#### 3. [Data Governance] Data Mesh & Discovery at Workiva
**S:** 200+ analysts needed access to domain-specific data while maintaining strict financial services compliance.
**T:** Build a data discovery and governance architecture with cell-level access control.
**A:** Pioneered Data Mesh using AWS Lake Formation with tag-based RBAC at cell level. Built Python ETL/Reverse ETL workflows. Automated infrastructure via Terraform/CloudFormation.
**R:** 200+ analysts with self-service access. Strict governance maintained. Foundation for real-time analytics.
**Reflection:** Data governance is a cultural change, not just a technical one. Domain teams need to own their data products.
**Best for:** Data Discovery & Governance sub-team interviews, "how do you balance access with governance."

#### 4. [Fault Tolerance] Zero-Downtime Mainframe Migration — Colorado Payroll
**S:** Colorado state government: 100K+ employee payroll records on legacy mainframe with 30+ years of schema drift. Zero downtime requirement.
**T:** Design and execute full migration to modern cloud architecture.
**A:** Built idempotent dbt + DuckDB + Redshift pipelines with sub-hour refresh (down from weekly batch). Designed reconciliation layer mapping 30+ years of schema changes. Architected AWS Step Functions + Fargate + Terraform.
**R:** 100K+ records migrated. Zero downtime. 30% cloud cost reduction. Sub-hour refresh.
**Reflection:** Legacy migrations are 80% data archaeology, 20% engineering. Proving correctness to stakeholders who lived with the old system for decades was the hardest part.
**Best for:** "Tell me about a complex system migration," "how do you ensure data correctness," system reliability.

#### 5. [Scale & Reliability] Platform Observability for 40+ Teams — VA.gov Watchtower
**S:** VA.gov needed unified observability across 40+ product teams serving 18M+ veterans. No centralized incident management.
**T:** Lead team of 4 to build unified observability platform.
**A:** Architected multi-source ETL pipeline (Python, Parquet, DuckDB). Aggregated Datadog, GitHub, Slack, PagerDuty. Established DORA metrics and Four Golden Signals as org-wide standards.
**R:** Platform became VA's standard for observability. Adopted by 40+ teams. Reduced MTTD for cross-system issues.
**Reflection:** Platform adoption is harder than platform building. Would invest more in documentation and onboarding from day one.
**Best for:** "Tell me about leading a cross-team initiative," "how do you drive adoption," Netflix culture (ownership, impact at scale).

#### 6. [Netflix Culture — Freedom & Responsibility] Autonomous Decision-Making at Ad Hoc
**S:** At Ad Hoc, worked as a remote Staff-level IC with high autonomy across federal contracts. No micromanagement — expected to identify problems, propose solutions, and ship.
**T:** Deliver mission-critical systems for VA, Colorado, HHS with minimal oversight.
**A:** Self-directed architecture decisions. Proposed and built Watchtower without being asked. Identified Colorado's mainframe risk and designed the migration path. Chose technology stacks (dbt, DuckDB, Argo) based on first-principles analysis.
**R:** Every major system shipped on time. Team grew from prototype to production under my technical direction.
**Reflection:** High autonomy works when you pair it with high accountability. I carried a pager for systems I built. Netflix's "Freedom & Responsibility" resonates because that's how I've always operated.
**Best for:** Culture fit interview, "why Netflix," "describe a time you took ownership."

#### 7. [Real-Time Systems] Sub-Second Event Processing — eCR Pipeline
**S:** Public health agencies needed real-time ingestion of electronic Case Reports — 50K+ events/day at sub-second latency.
**T:** Build scalable real-time pipeline with NLP-powered deduplication.
**A:** Event-driven architecture (Lambda, DynamoDB, S3). AWS Comprehend Medical for NLP. Verato for identity resolution. Modular rules registry for condition-specific workflows.
**R:** 50K+ events/day at sub-second latency. Automated data handling. Flexible rules registry enabled updates without redeployment.
**Reflection:** Real-time systems require different thinking than batch. Configurability (rules registry) was the key insight — separating policy from mechanism.
**Best for:** "Design a real-time data pipeline," "how do you handle schema evolution," Data Movement Platform sub-team.

#### 8. [Constrained Optimization] ML in Production Under Resource Limits — HHS Head Start
**S:** HHS Head Start needed semantic deduplication for free-form submissions. Cloud Foundry imposed 2GB memory ceiling.
**T:** Deploy BERT-based NLP dedup within severe resource constraints.
**A:** Lazy model loading, batch vectorization, optimized PyTorch serving. FastAPI + SpaCy + AWS Comprehend pipeline.
**R:** Sub-200ms inference. Eliminated duplicate records for 250K+ program staff. Improved reporting accuracy for $15.8B program.
**Reflection:** Constraints force innovation. Lazy loading and batch vectorization aren't fancy, but they're the difference between shipping and not.
**Best for:** "How do you handle performance constraints," "tell me about optimization," systems thinking.

### Netflix-Specific Prep Notes

- **Read the [Netflix Culture Memo](https://jobs.netflix.com/culture)** before any interview. Key values: People over Process, Freedom and Responsibility, Context not Control, Highly Aligned Loosely Coupled.
- **"Keeper Test" framing:** Netflix asks managers "would I fight to keep this person?" Frame your stories around being the person a team would fight to keep.
- **Candor is a value.** Be direct about the Java gap. Say "I've built systems in Go, Rust, and Python at similar complexity. I'll ramp on JVM quickly because I understand the underlying distributed systems patterns."
- **No "process for process sake."** Netflix rejects heavy methodology. Frame Argo Workflows and platform work as "removing toil" and "enabling autonomy," not "enforcing standards."
